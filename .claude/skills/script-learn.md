# /script-learn — Learning Engine

Читает сырой сценарий (TXT/PDF), разбирает его по [`core/parsing_matrix.md`](../../core/parsing_matrix.md)
и автоматически записывает структурированный референс в `training/screenplays/[movie_name].md`.

Это фоновый инженерный процесс, а не диалог с автором. `/script-learn` не ведёт дебаты для пользователя —
он готовит материал, которым позже будут пользоваться дебаты в `/script-doctor`.

**Обязательно к прочтению перед выполнением:** [`CLAUDE.md`](../../CLAUDE.md), особенно §1 (роster
модулей динамический), §5 (дисциплина `/script-learn`) и §3 (анти-штамп дисциплина Meta-Reference).
Все guardrails оттуда действуют здесь без исключений — успех фильма не даёт права смешивать модули
или сжимать развилки.

## Шаг 0: Определить текущий набор модулей

Прочитать список файлов в `training/books/`. Каждый — зарегистрированный модуль со своей схемой полей
(`module_schema` в frontmatter файла, см. `.claude/skills/book-learn.md`). Это и есть полный набор
модулей для разбора — ничего сверх реально зарегистрированного не подразумевается.

Если `training/books/` пуст — сообщить пользователю, что разбор пройдёт только по Base/Beat Layer,
без Module Layer (нет модулей — нечем анализировать характер и структуру теоретически), и спросить,
продолжать ли в таком виде или сначала добавить хотя бы один модуль через `/book-learn`.

## Шаги выполнения

### 1. Приём и нормализация текста

Прочитать файл (TXT/PDF), привести к единому текстовому представлению со стабильной нумерацией сцен.
Если формат сценария нестандартный (нет чёткой разбивки на сцены) — реконструировать разбивку по
слэглайнам (INT./EXT.) прежде чем переходить дальше.

### 2. Base Layer + Beat Layer

Пройти по тексту и выделить:
- координаты (`act`, `scene_range`, `characters_present`, `pov_character`) для Base Layer;
- сюжетные события и присвоить им `beat_id` — короткий, нейтральный, описательный слаг
  (`ally-betrayal-reveal`, не `truby-moral-flaw-exposed`). `beat_id` не должен содержать имени модуля
  или интерпретации — это чисто структурный индекс (см. CLAUDE.md §5, слой индексации).

### 3. Module Layer — независимый разбор по всем зарегистрированным модулям

Для каждого модуля из `training/books/` заполнить его поля (по его собственной `module_schema`) для
каждого значимого `beat_id`, **независимо от остальных модулей**. Не проверять по ходу заполнения,
согласуются ли модули между собой — согласование не является целью этого шага.

Каждый модуль отвечает только на свои собственные вопросы, в своих терминах. Не использовать
[`term_correspondence_map.md`](../../core/term_correspondence_map.md) для того, чтобы «досчитать» одно
поле по значению другого — карта соответствий существует для объяснений в дебатах, а не для автозаполнения.

### 4. Фиксация развилок (даже для успешного фильма)

Если два и более модуля расходятся в диагнозе одного `beat_id` — записать это как `fork`, в точности
как это делает `/script-doctor`. **Тот факт, что фильм успешен и снят, не является тай-брейкером.**
Признание одного модуля «более правым» только потому, что фильм сработал в прокате — запрещённая
операция (CLAUDE.md §5). При одном зарегистрированном модуле форков не бывает по определению —
это не ошибка, а следствие текущего размера roster'а.

### 5. Meta-Reference разметка

Для каждого `beat_id` заполнить блок `meta_reference` из `parsing_matrix.md`:

- `function_tag` — заполняется сейчас: какую функцию этот beat выполняет для конкретного героя этого
  фильма, в терминах реально зарегистрированных модулей. Не описание события, а его роль в судьбе
  персонажа.
- `default_deviation` — заполняется сейчас, если применимо: чем это исполнение отличается от
  предсказуемого по умолчанию хода в этой точке жанра (если дефолт для этого слота уже известен
  системе по ранее выученным сценариям того же жанра).
- `variance_axis` / `variance_position` — заполняются как **предварительные** (`provisional: true`).
  Точное положение на оси дисперсии зависит от всего пула сценариев жанра, а не только от этого
  фильма, и пересчитывается заново на Шаге 6.

Функция должна объяснять «зачем», а не пересказывать «что» — если формулировка function_tag могла бы
без изменений подойти к любому фильму этого жанра, она недостаточно специфична.

### 6. Обновление пула жанра

После записи нового сценария — пересчитать `variance_axis` / `variance_position` для всех сценариев
того же `genre_type` в `training/screenplays/`, снять флаг `provisional`. Один новый эталон может
сдвинуть представление о том, что в жанре «частая реализация», а что «редкая» — variance-карта жанра
должна оставаться согласованной по всему пулу, а не только внутри одного файла.

### 7. YAML frontmatter и запись файла

Собрать метаданные и записать итоговый файл:

```yaml
---
title: <str>
year: <int|null>
genre_type: <str>
tropes: [str]              # для быстрого поиска по /script-doctor Шаг 2
protagonist: <str>
modules_used: [str]        # module_key всех модулей, участвовавших в этом разборе
learned_at: <ISO date>
provisional_variance: <bool>  # true, если Шаг 6 ещё не выполнен для всего пула
---
```

Путь: `training/screenplays/[movie_name-slug].md`. Если файл с таким именем уже существует —
не перезаписывать молча; сообщить пользователю и спросить, обновить ли существующий разбор.

## Вывод пользователю

Краткое резюме в терминале — не полноценные дебаты (это территория `/script-doctor`):
- по каким модулям прошёл разбор (`modules_used`);
- сколько `beat_id` размечено;
- сколько зафиксировано `fork` между модулями и по каким beat;
- путь к записанному файлу;
- если пул жанра был пересчитан — сколько других сценариев жанра затронуто пересчётом.

Не выводить развёрнутую критику фильма — `/script-learn` фиксирует референс, а не оценивает его.
