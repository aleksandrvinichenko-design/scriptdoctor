# Parsing Matrix — модульная схема разбора сценария

Эта схема используется и `/script-learn`, и `/script-doctor` для разбора любого текста (черновик автора
или эталонный сценарий) на единую структуру данных. Правила неусреднения и неразрешения развилок из
[`CLAUDE.md`](../CLAUDE.md) обязательны при заполнении этой схемы.

Схема состоит из трёх слоёв: **Base Layer** (нейтральные координаты), **Beat Layer** (событийная
разметка) и **Author Modules** (четыре независимых, ничем не упрощённых блока). Base и Beat Layer никогда
не содержат авторской терминологии — они существуют только для того, чтобы у всех модулей была общая
точка адресации.

---

## Base Layer — структурные координаты

Присваивается каждому анализируемому фрагменту. Это адрес, а не интерпретация.

```yaml
coordinate:
  act: <int>                # 1 / 2A / 2B / 3 — либо иная принятая для жанра структура
  scene_range: <str>        # напр. "34-37" — номера сцен или диапазон страниц
  characters_present: [str] # действующие лица в этом фрагменте
  pov_character: <str|null> # чья точка зрения ведёт фрагмент, если применимо
```

Base Layer не отвечает на вопрос «что это значит». Он отвечает только на вопрос «где это находится».

## Beat Layer — событийная разметка

Story beat — минимальная драматургическая единица: конкретное сюжетное событие, а не номер страницы.
Один beat может охватывать несколько сцен из Base Layer или их часть.

```yaml
beat:
  beat_id: <slug>            # напр. "ally-betrayal-reveal"
  description: <str>         # одна фраза, нейтральный факт: "герой узнаёт о предательстве союзника"
  coordinate_ref: <coordinate.scene_range>  # привязка к Base Layer
```

`beat_id` — это тот самый нейтральный индексирующий лейбл, о котором говорится в §5 `CLAUDE.md`. Он
не интерпретирует событие, не принадлежит ни одной школе и используется исключительно для поиска и
сопоставления жанров при синтезе Meta-Reference. Все нижеследующие авторские модули привязываются
к `beat_id`, а не наоборот — это то, что позволяет debate-движку понять, что несколько школьных вердиктов
относятся к одному и тому же моменту истории.

## Author Modules

Каждый модуль заполняется независимо. Поля — это собственные аналитические вопросы автора книги,
не переформулированные и не упрощённые. Пустое поле в одном модуле не означает, что нужно заполнить его
данными из другого модуля.

### Howard Module (David Howard — физическая причинность)

```yaml
howard:
  beat_id: <ref>
  causal_link_from: <beat_id|null>   # из какого предыдущего beat это событие следует физически
  causal_link_necessity: <str>       # почему это следствие, а не совпадение
  capacity_of_will: <str>            # проявляет ли герой волю действовать, или событие происходит "с ним"
  irreversibility: <bool>            # можно ли откатить это событие без разрушения цепочки
```

### McKee Module (Robert McKee — глубинные ценности)

```yaml
mckee:
  beat_id: <ref>
  want: <str>                        # осознанная, декларируемая цель героя
  need: <str>                        # то, что герою на самом деле нужно, часто не осознаётся им
  true_character_vs_characterization: <str>  # что этот момент раскрывает под давлением, в отличие от привычного поведения
  value_at_stake: <str>              # какая ценность (жизнь/смерть, любовь/ненависть и т.д.) заряжена в этом моменте
  value_charge: <"+"|"-"|"+/-">      # знак заряда ценности после этого beat
```

### Truby Module (John Truby — моральная структура)

```yaml
truby:
  beat_id: <ref>
  ghost: <str>                       # травма прошлого, довлеющая над героем
  psychological_flaw: <str>          # изъян, вредящий прежде всего самому герою
  moral_flaw: <str>                  # изъян, вредящий окружающим через действия героя
  moral_argument_step: <str>         # на каком шаге морального аргумента находится этот beat
  self_revelation_progress: <"none"|"partial"|"full">  # насколько герой приблизился к самопознанию
```

### Snyder Module (Blake Snyder — коммерческая структура)

```yaml
snyder:
  beat_id: <ref>
  beat_sheet_slot: <str>             # напр. "Catalyst", "Midpoint", "All Is Lost" — из 15 биatов Snyder
  genre_type: <str>                  # один из авторских "типов" Snyder (Monster in the House, Golden Fleece и т.д.)
  theme_stated_echo: <bool>          # перекликается ли этот момент с темой, заявленной в начале
  b_story_link: <str|null>           # связь с побочной сюжетной линией, если есть
```

## Meta-Reference поля (заполняются только для эталонных сценариев в `training/screenplays/`)

Эти поля добавляются поверх Author Modules при разборе эталонного сценария в рамках `/script-learn`
и используются исключительно для синтеза Meta-Reference (см. `.claude/skills/script-learn.md`).

```yaml
meta_reference:
  beat_id: <ref>
  function_tag: <str>          # драматургическая функция beat для want/need/flaw ЭТОГО героя (function-over-form)
  variance_axis: <str>         # к какой оси вариации внутри жанра относится это исполнение
  variance_position: <str>     # инвариант / частая реализация / редкая реализация — где именно на оси
  default_deviation: <str|null> # как это исполнение уклоняется от жанрового дефолта в этой точке (опционально)
```

## Развилки (Forks)

Когда два и более модуля дают несовместимые диагнозы одного `beat_id`, это фиксируется отдельной
структурой, а не переписыванием одного из полей:

```yaml
fork:
  beat_id: <ref>
  conflicting_schools: [str]   # напр. ["truby", "mckee"]
  positions:
    - school: <str>
      claim: <str>
  resolved_by: <"author"|null> # null пока автор не сделал выбор через интерактивное поле `[ ]`
  resolution: <str|null>
```

Развилка никогда не блокирует прогресс по pipeline (см. `core/pipeline_config.md`) — это чисто
рекомендательная структура.
