# Pipeline Config — гейты стадий

Три стадии: **Logline → Character → Treatment**. Переход между ними регулируется правилом A+D из
[`CLAUDE.md §4`](../CLAUDE.md#4-блокировка-стадий--узкая-и-нейтральная-к-школам):

- **(A) Пустые обязательные поля** — блокирует.
- **(D) Жёсткий, нейтральный к школам чек-лист структурного отсутствия** — блокирует.
- Теоретические развилки между школами (§2 CLAUDE.md) — **никогда не блокируют**.
- Результат Empirical Crash-Test (§3 CLAUDE.md) — **никогда не блокирует**, только советует.

Если гейт останавливает прогресс по причине, не входящей в списки ниже — это ошибка конфигурации,
а не ожидаемое поведение.

---

## Стадия 1: Logline

### (A) Обязательные поля

```yaml
required_fields:
  - protagonist.name
  - protagonist.external_goal      # mckee.want для протагониста
  - central_obstacle
  - genre_type                     # snyder.genre_type
```

### (D) Чек-лист структурного отсутствия

```yaml
hard_checks:
  - id: active_protagonist
    fail_if: "протагонист не совершает ни одного действия для достижения цели — только реагирует на события"
  - id: stated_external_goal
    fail_if: "external_goal не сформулирована как конкретный, проверяемый результат"
  - id: obstacle_exists
    fail_if: "central_obstacle отсутствует или тождественен самому протагонисту без внешнего или внутреннего препятствия"
```

Ничего в этой стадии не проверяет качество или глубину логлайна — это территория дебатов на
`/script-doctor`, а не гейта.

---

## Стадия 2: Character

### (A) Обязательные поля

```yaml
required_fields:
  - mckee.want
  - mckee.need
  - truby.psychological_flaw
  - truby.moral_flaw
  - truby.ghost
  - howard.capacity_of_will
```

Поле считается пустым, если оно отсутствует или дословно совпадает с полем другой школы (то есть
было скопировано, а не заполнено самостоятельно — см. запрет на слияние терминов в CLAUDE.md §1).

### (D) Чек-лист структурного отсутствия

```yaml
hard_checks:
  - id: want_need_distinction
    fail_if: "want и need сформулированы идентично — нет внутреннего конфликта персонажа"
  - id: flaw_has_ghost
    fail_if: "moral_flaw или psychological_flaw заявлены, но ghost не указан или не связан с ними причинно"
  - id: flaw_is_actionable
    fail_if: "flaw описан как черта характера в прошедшем времени без последствий в настоящем действии сценария"
```

Расхождение школ в диагнозе конкретного flaw (например, Truby и McKee по-разному читают один и тот же
момент) фиксируется как fork в `parsing_matrix.md` и **не является причиной блокировки** — гейт
проверяет только структурное наличие ответа, не согласие школ по его содержанию.

---

## Стадия 3: Treatment

### (A) Обязательные поля

```yaml
required_fields:
  - beats[]                        # полная последовательность story beat из Beat Layer
  - beats[].coordinate_ref
  - snyder.beat_sheet_slot          # хотя бы для ключевых поворотных точек
```

### (D) Чек-лист структурного отсутствия

```yaml
hard_checks:
  - id: causal_chain_intact
    fail_if: "существует beat, для которого howard.causal_link_from не указывает ни на один предыдущий beat, и это не первый beat истории"
  - id: act_coverage
    fail_if: "хотя бы один акт не содержит ни одного beat с непустым snyder.beat_sheet_slot"
  - id: no_orphan_scenes
    fail_if: "сцена из Base Layer не привязана ни к одному beat_id"
  - id: midpoint_present
    fail_if: "во всей истории нет ни одного beat в позиции, эквивалентной середине истории"
```

Все остальные вопросы на этой стадии — глубина проработки Meta-Reference, наличие клише, оригинальность
исполнения относительно оси дисперсии — обрабатываются в Empirical Crash-Test (Шаг 2–3 `/script-doctor`)
и **никогда не блокируют** переход. Автор может осознанно принять черновик со слабым Crash-Test
результатом и двигаться дальше.
