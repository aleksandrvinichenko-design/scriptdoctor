# Script-Doctor AI

Script-Doctor AI — аналитический фреймворк для сценаристов, работающий поверх Claude Desktop / Claude
Code. Он не пишет текст за автора. Он стресс-тестирует уже существующие идеи автора двумя независимыми
способами: спором четырёх несовместимых школ сценарного мастерства и сверкой с эмпирическим эталоном,
синтезированным из реально снятых сценариев.

## Философия в двух правилах

1. **Школы никогда не сливаются в один вердикт.** David Howard (причинность), Robert McKee (глубинные
   ценности), John Truby (моральный изъян) и Blake Snyder (коммерческая структура) могут прийти к
   несовместимым диагнозам одной и той же сцены — и это ожидаемый результат, а не ошибка. Система
   показывает развилку как есть; решать — автору.
2. **Эмпирический эталон ищет функцию, а не форму.** Meta-Reference, синтезируемый из эталонных
   сценариев, не является списком «что чаще всего происходит в жанре» — это и есть штамп. Система ищет,
   какую драматургическую функцию выполняет структурный ход, и сравнивает функцию, а не поверхностное
   сходство событий.

Полное обоснование этих правил — в [`CLAUDE.md`](CLAUDE.md).

```text
claude-script-doctor/

├── core/

│   ├── term_correspondence_map.md  Справочник пересечений терминов между школами (только для чтения)

├── .claude/
│   └── skills/
│       ├── script-learn.md      Логика команды /script-learn
│       └── script-doctor.md     Логика команды /script-doctor
├── training/

```

## Установка

1. Разместите эту папку как проект в Claude Code (или откройте её как рабочую директорию).
2. Claude Code автоматически подхватит `CLAUDE.md` как системные правила проекта и найдёт скиллы
   в `.claude/skills/`.
3. Наполните `training/books/` материалами по четырём теоретикам — по одному файлу или набору файлов
   на автора (например, `howard.md`, `mckee.md`, `truby.md`, `snyder.md`). Эти файлы формируют базу,
   на которую опираются Author Modules при разборе (см. `core/parsing_matrix.md`).
4. `training/screenplays/` изначально пуст — он наполняется постепенно через `/script-learn`.

## Использование

### `/script-learn [путь_к_сырому_сценарию]`

Разбирает эталонный (уже снятый) сценарий и записывает структурированный референс в
`training/screenplays/[название].md`. Чем больше сценариев разобрано в конкретном жанре, тем надёжнее
Meta-Reference при последующей работе `/script-doctor` в этом жанре.

```
/script-learn ./raw/heat_1995.pdf
```

### `/script-doctor [путь_к_черновику_автора]`

Запускает 3-шаговую валидацию черновика:

1. **Theory** — дебаты четырёх школ, развилки фиксируются явно.
2. **Empirical Synthesis** — подбор релевантных эталонных сценариев по жанру и синтез Meta-Reference.
3. **Crash-Test** — сверка черновика с Meta-Reference на предмет штампов (по функции, не по форме).

```
/script-doctor ./drafts/my_thriller_v3.fdx
```

Вывод — короткий диалог школ в терминале с интерактивными полями `[ ]` там, где решение требует выбора
автора. Прогресс по стадиям (Logline → Character → Treatment) может быть заблокирован только при
отсутствии обязательных структурных элементов (см. `core/pipeline_config.md`) — никогда из-за
разногласия школ и никогда из-за результата Crash-Test.

## Что важно понимать перед использованием

- Система не скажет вам «это правильно» или «это неправильно» в едином голосе. Если вы ждёте одного
  чёткого вердикта — вы получите вместо этого структурированное разногласие и вопрос, что с ним делать.
- Совпадение с частым паттерном жанра само по себе не штраф. Штраф — только если этот паттерн у вас
  ничего не делает для конкретно вашего героя.
- Чем беднее `training/screenplays/` в вашем жанре, тем менее надёжен Crash-Test. Система явно
  предупредит, если выборка мала.
