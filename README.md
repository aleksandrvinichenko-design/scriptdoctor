# Script-Doctor AI

Script-Doctor AI — аналитический фреймворк для сценаристов, работающий поверх Claude Desktop / Claude
Code. Он не пишет текст за автора. Он стресс-тестирует уже существующие идеи автора двумя независимыми
способами: спором независимых теоретических модулей и сверкой с эмпирическим эталоном, синтезированным
из реально снятых сценариев.

## Философия в трёх правилах

1. **Roster модулей не зашит заранее.** Фреймворк не поставляется с фиксированным набором теоретиков.
   `training/books/` пуст с самого начала — каждый модуль появляется только через `/book-learn`, и
   система работает ровно с тем, что реально добавлено: ноль книг — ноль модулей, одна книга — один
   голос, две и больше — начинается настоящий спор.
2. **Модули никогда не сливаются в один вердикт.** Как только зарегистрировано два и более модуля, они
   могут прийти к несовместимым диагнозам одной и той же сцены — и это ожидаемый результат, а не ошибка.
   Система показывает развилку как есть; решать — автору.
3. **Эмпирический эталон ищет функцию, а не форму.** Meta-Reference, синтезируемый из эталонных
   сценариев, не является списком «что чаще всего происходит в жанре» — это и есть штамп. Система ищет,
   какую драматургическую функцию выполняет структурный ход, и сравнивает функцию, а не поверхностное
   сходство событий.

Полное обоснование этих правил — в [`CLAUDE.md`](CLAUDE.md).

## Структура репозитория

```text
claude-script-doctor/
├── CLAUDE.md                    Глобальные правила и guardrails дебатов
├── core/
│   ├── parsing_matrix.md        Base/Beat Layer + контракт модуля (Module Layer) — без списка модулей
│   ├── term_correspondence_map.md  Живой справочник пересечений терминов, пополняется по мере /book-learn
│   └── pipeline_config.md       Гейты стадий Logline → Character → Treatment, не зависят от roster'а
├── .claude/
│   └── skills/
│       ├── book-learn.md        Логика команды /book-learn
│       ├── script-learn.md      Логика команды /script-learn
│       └── script-doctor.md     Логика команды /script-doctor
├── training/
│   ├── books/                   Пуст изначально — по одному .md на модуль, создаётся через /book-learn
│   └── screenplays/             Разобранные эталонные сценарии (заполняется через /script-learn)
└── README.md
```

## Установка

1. Разместите эту папку как проект в Claude Code (или откройте её как рабочую директорию).
2. Claude Code автоматически подхватит `CLAUDE.md` как системные правила проекта и найдёт скиллы
   в `.claude/skills/`.
3. `training/books/` и `training/screenplays/` изначально пусты. Никакой набор теоретиков не
   предполагается заранее — весь Theoretical Consensus Layer строится из того, что вы реально добавите
   через `/book-learn`.

## Использование

### `/book-learn [путь_к_книге] [module_key?]`

Разбирает книгу по сценарному мастерству и регистрирует новый модуль: пишет дистиллированную базу
знаний и машиночитаемую схему полей в `training/books/[module_key].md` — своими словами, с
диагностическими вопросами для дебатов, без пересказа близко к тексту. Схема поля выводится из
содержания именно этой книги, а не подгоняется под уже существующие модули.

```
/book-learn ./raw/truby_anatomy_of_story.pdf truby
```

Добавьте столько книг, сколько хотите использовать в дебатах — их может быть одна, три или десять,
это не ограничено фреймворком.

### `/script-learn [путь_к_сырому_сценарию]`

Разбирает эталонный (уже снятый) сценарий по всем модулям, зарегистрированным на момент запуска, и
записывает структурированный референс в `training/screenplays/[название].md`. Чем больше сценариев
разобрано в конкретном жанре, тем надёжнее Meta-Reference при последующей работе `/script-doctor`
в этом жанре.

```
/script-learn ./raw/heat_1995.pdf
```

### `/script-doctor [путь_к_черновику_автора]`

Запускает 3-шаговую валидацию черновика по текущему roster'у модулей:

1. **Theory** — дебаты зарегистрированных модулей, развилки фиксируются явно.
2. **Empirical Synthesis** — подбор релевантных эталонных сценариев по жанру и синтез Meta-Reference.
3. **Crash-Test** — сверка черновика с Meta-Reference на предмет штампов (по функции, не по форме).

```
/script-doctor ./drafts/my_thriller_v3.fdx
```

Вывод — короткий диалог модулей в терминале с интерактивными полями `[ ]` там, где решение требует
выбора автора. Прогресс по стадиям (Logline → Character → Treatment) может быть заблокирован только при
отсутствии обязательных структурных элементов (см. `core/pipeline_config.md`) — никогда из-за
разногласия модулей и никогда из-за результата Crash-Test.

## Что важно понимать перед использованием

- До первого `/book-learn` система умеет разбирать только структуру (Base/Beat Layer) — без
  теоретического слоя анализировать персонажа и мотивацию нечем.
- С одним зарегистрированным модулем дебатов не будет — будет один голос без оппонентов, и это
  ожидаемое, а не ошибочное поведение.
- Система не скажет вам «это правильно» или «это неправильно» в едином голосе. Если вы ждёте одного
  чёткого вердикта — вы получите вместо этого структурированное разногласие и вопрос, что с ним делать.
- Совпадение с частым паттерном жанра само по себе не штраф. Штраф — только если этот паттерн у вас
  ничего не делает для конкретно вашего героя.
- Чем беднее `training/screenplays/` в вашем жанре, тем менее надёжен Crash-Test. Система явно
  предупредит, если выборка мала.
